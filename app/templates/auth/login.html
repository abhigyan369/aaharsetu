WHY POST /pages/login instead of /auth/login? - POST /auth/login returns JSON with the JWT token. - A plain HTML form follows the redirect/response as a page load. - We can't set an httpOnly cookie from JS (that's the whole point of httpOnly). - Solution: POST /pages/login is a server-side handler that: 1. Verifies credentials (same logic as /auth/login) 2. Sets the httpOnly cookie via Set-Cookie header 3. Redirects the browser to the appropriate dashboard - This way the browser makes a normal form POST, the server sets the cookie, and the browser follows the redirect — pure server-side, no JS needed. NOTE: This form uses a plain
POST, not fetch(). Why? Because we WANT the browser to follow the redirect that the server sends back (302 → /dashboard).
